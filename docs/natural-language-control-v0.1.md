# 自然语言控制 MCU：v0.1 实施提案

状态：负责人已同意实施；PC 入口与离线验证已交付，真实 AI 与开发板待验收。日期：2026-11-03。

## 解决的问题

用户用一句中文描述想看到的运动，系统将文字转换成明确的运动计划，检查后在 51 单片机的 8×8 LED 点阵上演示。用户不必手写轨迹点或修改 C++ 起终点。

第一版的“运动”是光点位置随时间变化，执行器是现有 LED 点阵，不是电机。它验证“理解指令—生成计划—执行—报告结果”的闭环。未来接入机器人需要另行设计执行器、物理单位、反馈及控制约束，本次不实施，也不宣称已有机器人控制能力。

## 用户流程

1. 输入文字，例如“从左下角走到 (2,4)，然后以 (4,4) 为圆心、半径两格顺时针画一圈”。
2. AI 返回运动计划，或者提出一条补充问题。
3. 程序检查完整计划，显示动作顺序、坐标、用时、默认值，并生成本地轨迹预览。
4. 用户在预览会话中明确选择执行，程序才打开指定串口。环境变量中存在端口不构成新模式的执行指令。
5. PC 按节拍发送点位，记录发送进度、ACK 和结束状态；失败时停止后续发送，报告已发送到哪里。

“画个圆”可采用公开的默认圆心 (3.5,3.5)、半径 2 格、用时 4 秒，并将到圆周起点的连接直线作为独立动作展示；用户确认后执行。“再快一点”在第一版无历史上下文时请求完整指令，不猜测。超出动作集合的“去拿杯子”等指令说明暂不支持。

计划预览只证明程序打算执行什么。第一版没有位置传感器，不能仅凭 ACK 宣称实际运动正确或完成物理闭环。

## 模块职责

| 模块 | 输入 → 输出 | 必须满足的边界 |
|---|---|---|
| 指令入口 | UTF-8 文字 → 请求 | 限制长度；提供固定工作区与动作定义 |
| AI 适配器 | 请求 → ready / clarification | 不直接调用串口；失败不退回 fakeAI 或随机轨迹 |
| 计划解析和校验 | JSON → 类型明确的 MotionPlan | 所有字段、范围和资源上限通过后才交付执行器 |
| 轨迹编译器 | MotionPlan → 带时间戳的点序列 | 确定性生成；整圆回到起点；多动作坐标一致 |
| 预览执行器 | 点序列 → CSV / 简单 SVG 与说明 | 无网络、无硬件也可重复验证；产物标明计划来源 |
| MCU 执行器 | 点序列 → 帧、串口、运行报告 | 有界等待、逐帧发送、出错停止；不得在读取计划时启动 |

MATLAB 保留为独立轨迹分析和对照工具，不作为自然语言模式的必经输入。原 A* 与 fakeAI 保留在旧演示路径；本版没有障碍物建模，不宣传避障能力。

新增入口建议命名为 MotionControl；旧 TrajectorySystem 在迁移期保留，但其环境变量触发串口的行为须在文档中单独说明，不能当作新模式的执行保护。新入口与旧程序共享经测试的基础模块，禁止默认调用旧 main()。

## 计划契约：motion-plan/1

工作区使用 LED 格坐标，x 向右、y 向上，左下角为 (0,0)，两轴范围均为 [0,7]，允许小数。不是毫米或电机转数。

外层输出两种互斥形式：

- ready：仅含 status、summary、defaults、plan。plan 必须完整，defaults 列明模型采用的默认值。
- clarification：仅含 status、question。没有可执行计划，不打开串口。

ready 的完整样例见 [natural-language-plan.example.json](natural-language-plan.example.json)。以下字段规范是实施依据：

| 字段 | 类型与规则 |
|---|---|
| version | 整数，必须为 1 |
| workspace | 字符串，必须为 led8x8 |
| start | 含 x、y 两个有限数的对象；预览时展示初始点 |
| tickMs | 整数，第一版固定为 50 |
| repeat | 整数，1–10；重复整个 actions，重复时末点必须等于初点 |
| actions | 1–16 个动作，按顺序执行 |
| line | type、to、durationMs；从当前点走到 to；to 只含 x、y |
| circle | type、center、radius、clockwise、durationMs；从当前点绕 center 走完整一圈；当前点须在圆周上 |
| wait | type、durationMs；保持当前位置 |

durationMs 为 50 的正整数倍。展开重复后的计划总时长不超过 60 秒，采样点数不超过 4096。原始文字不超过 1000 个 Unicode 字符；提供方响应不超过 64 KiB、JSON 嵌套深度不超过 16；summary、defaults、question 也设置独立长度上限。

拒绝未知字段、重复对象键、类型错误、缺字段、非有限数、越界点、半径不大于零、圆周出界和不连续的重复。起点与圆周位置比较使用明确的数值容差 1e-6 格；不通过裁剪或重缩放掩盖错误。校验失败不生成可执行产物。

轨迹在 t=0 包含初始点，每 50ms 采样一次，动作终点精确包含一次；相邻动作共享的边界不重复插入。直线按时间线性插值；圆按角度线性插值，以当前点推导初始角度；等待不改变坐标。第一版不生成机械设备的速度或加速度指令，帧中的 vx、vy 固定为零。

## 固定映射、节拍与失败处理

新模式两轴始终采用 q=round(value/7×65535) 编码，q 在 [0,65535]。不同动作共用工作区，不按各自最小/最大坐标拉伸。旧 encodeFrames 的自动量化逻辑保留为旧示例接口。位置量化只用于 LED 显示，不足以支持未来电机控制。

新执行器先清理主机接收缓冲，每次仅发送一帧，等待 0xCC 加一字节计数 ACK。首个 ACK 只建立计数基线，后续计数需按模 256 增长。它不是请求 ID，无法区分所有迟到 ACK；首次上板须复位开发板并确认空队列，本版不允许中断后无复位地自动恢复。

ACK 超时默认 1000ms，采用单调时钟计算真实经过时间；错误或超时停止，不盲目重发。按 50ms 理想时间表调度，未完成 ACK 不发下一帧；延迟超过一拍就中止并报告，不追赶发送积压帧。Windows 调度不提供硬实时保证。

取消操作表示 PC 停止发送，LED 可能停在最后一点。现有协议没有远程停机命令，不把它称作硬件急停。收到 ACK 只说明固件处理了该帧并更新显示缓冲，不能验证 LED 光学显示或机械运动。

## AI 调用规则

沿用 DeepSeek 作为首个适配器，密钥仅从本机环境读取。提示词给出工作区、动作集合和契约；解析提供方响应包后，再独立解析和校验模型内容。正常情况下模型不输出逐个采样点，点序列由本地编译器生成。

新链路使用正常 TLS 证书和主机名校验，不继承现有 DSAI.cpp 中忽略证书校验的设置。设置连接、发送、接收超时及整体请求截止时间；错误日志不输出密钥、完整响应或用户原文。无密钥、网络失败、模型拒答、无效 JSON 或不合法计划均返回可解释错误且不发送任何帧。

离线固定样例标明 source=fixture；本地计划文件标明 source=file；只有真实在线响应标明 source=ai。不得以固定规则或样例运行冒充 AI 实测。真实 API 测试需要负责人提供并授权使用密钥，不在本提案阶段调用。

## 实施顺序与验收

| 阶段 | 交付 | 必须通过的验收 |
|---|---|---|
| 1：离线核心 | 计划类型、严格解析、校验、直线/整圆/等待编译器、CSV/SVG 预览 | 固定计划产生确定端点/时长；所有非法计划拒绝；不触网、不打开串口 |
| 2：在线理解 | WinHTTP AI 适配器、中文输入、澄清和计划预览 | 提供方响应录制样例覆盖成功/拒答/错误；密钥缺失、超时和损坏 JSON 均零串口写入；真实 AI 单独授权验收 |
| 3：执行链路 | 固定映射编码、逐帧 ACK 执行器、取消和运行报告 | C++ 编码交给真实 firmware/protocol.c 在主机解码；假串口验证节拍/ACK/超时/部分失败；新入口默认只预览 |
| 4：上板联调 | 明确板型、接线、可重复固件构建和操作步骤 | 烧录、角点定位、整圆、重复、断连和停止实测；记录视频/日志；失败项不能标完成 |

三个固定验收输入：

1. “从 (0,0) 到 (2,4) 用两秒，再以 (4,4) 为圆心、半径两格顺时针画一圈，用四秒。”计划总时长 6 秒、121 个采样点；圆从 (2,4) 出发并回到该点。
2. “从 (0,0) 到 (7,0)，一秒，再回到 (0,0)，一秒，重复三次。”总时长 6 秒、121 个采样点；全程 y=0，不拉伸 y 轴。
3. “向右移动一百格。”越界，零串口写入，说明工作区范围。

不同中文表述可录为语义等价样例，但离线录制响应仅验证解析与执行，不证明在线模型理解准确率。实施后另用多条人工核对的中文指令进行在线评估。

CI 应覆盖 Windows MSVC、Linux GCC/Clang 的离线测试；调整 PR 分支过滤，确保本次依赖链上的 PR 实际触发检查。计划核心测试必须在 Release 有效，不能依赖被 NDEBUG 删除的断言。构建、模拟器通过与上板通过分别记录。
